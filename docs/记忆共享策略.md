## 核心概念

### storage-path 决定记忆范围

`--storage-path` 参数决定了记忆文件的存储位置，从而决定了记忆的共享范围：

```
不同的 storage-path = 独立的记忆库
相同的 storage-path = 共享的记忆库
```

### 默认行为

如果不指定 `--storage-path`，系统会使用默认路径：

```
Windows: C:\Users\YourName\.adaptive-agent\memory
macOS:   /Users/YourName/.adaptive-agent/memory
Linux:   /home/yourname/.adaptive-agent/memory
```

**这意味着**: 所有不指定路径的 AI 应用都会共享这个全局记忆库！

## 三种记忆模式

### 模式 1: 全局共享记忆 (Global Memory)

**配置**: 不指定 `storage-path` 或使用相同的全局路径

**效果**: 所有 AI 应用共享同一个记忆库

**适用场景**:
- 个人助手 (跨应用的统一记忆)
- 知识管理 (统一的知识库)
- 学习笔记 (所有 AI 都能访问)

**配置示例**:

```json
// VS Code 配置
{
  "mcpServers": {
    "adaptive-agent-mcp": {
      "command": "python",
      "args": [
        "C:/path/to/server.py"
        // 不指定 --storage-path，使用默认全局路径
      ]
    }
  }
}

// Claude Desktop 配置
{
  "mcpServers": {
    "adaptive-memory": {
      "command": "python",
      "args": [
        "C:/path/to/server.py"
        // 同样不指定，使用相同的默认路径
      ]
    }
  }
}
```

**结果**: VS Code 中的 AI 和 Claude Desktop 共享记忆！

```
┌─────────────────┐
│   VS Code AI    │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────┐
│  ~/.adaptive-agent/memory       │  ← 全局共享记忆库
│  (Global Shared Memory)         │
└─────────────────────────────────┘
         ▲
         │
┌────────┴────────┐
│ Claude Desktop  │
└─────────────────┘
```

### 模式 2: 项目隔离记忆 (Project-Specific Memory)

**配置**: 每个项目使用独立的 `storage-path`

**效果**: 不同项目的记忆完全隔离

**适用场景**:
- 多个独立项目
- 客户项目隔离
- 工作/个人分离

**配置示例**:

```json
// 项目 A 的配置
{
  "mcpServers": {
    "adaptive-agent-mcp": {
      "command": "python",
      "args": [
        "${workspaceFolder}/adaptive_agent_mcp/server.py",
        "--storage-path",
        "${workspaceFolder}/project_a_memory"  // 项目 A 的记忆
      ]
    }
  }
}

// 项目 B 的配置
{
  "mcpServers": {
    "adaptive-agent-mcp": {
      "command": "python",
      "args": [
        "${workspaceFolder}/adaptive_agent_mcp/server.py",
        "--storage-path",
        "${workspaceFolder}/project_b_memory"  // 项目 B 的记忆
      ]
    }
  }
}
```

**结果**: 项目 A 和项目 B 的记忆完全独立

```
┌─────────────────┐
│   项目 A        │
│   AI Agent      │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────┐
│  project_a_memory/              │
│  (项目 A 专属记忆)               │
└─────────────────────────────────┘

┌─────────────────┐
│   项目 B        │
│   AI Agent      │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────┐
│  project_b_memory/              │
│  (项目 B 专属记忆)               │
└─────────────────────────────────┘
```

### 模式 3: 混合模式 (Hybrid Mode)

**配置**: 部分应用共享全局记忆，部分使用项目记忆

**效果**: 灵活的记忆共享策略

**适用场景**:
- 个人知识库 (全局) + 项目记忆 (隔离)
- 通用助手 (全局) + 专项任务 (隔离)

**配置示例**:

```json
// Claude Desktop - 全局记忆 (个人助手)
{
  "mcpServers": {
    "adaptive-memory": {
      "command": "python",
      "args": [
        "C:/path/to/server.py",
        "--storage-path",
        "C:/Users/You/Documents/GlobalMemory"  // 全局记忆
      ]
    }
  }
}

// VS Code 项目 A - 项目记忆
{
  "mcpServers": {
    "adaptive-agent-mcp": {
      "command": "python",
      "args": [
        "${workspaceFolder}/server.py",
        "--storage-path",
        "${workspaceFolder}/project_memory"  // 项目记忆
      ]
    }
  }
}

// VS Code 项目 B - 也使用全局记忆
{
  "mcpServers": {
    "adaptive-agent-mcp": {
      "command": "python",
      "args": [
        "${workspaceFolder}/server.py",
        "--storage-path",
        "C:/Users/You/Documents/GlobalMemory"  // 共享全局记忆
      ]
    }
  }
}
```

**结果**: Claude Desktop 和项目 B 共享全局记忆，项目 A 独立

```
┌─────────────────┐     ┌─────────────────┐
│ Claude Desktop  │     │   项目 B        │
└────────┬────────┘     └────────┬────────┘
         │                       │
         └───────────┬───────────┘
                     ▼
         ┌─────────────────────────────────┐
         │  GlobalMemory/                  │
         │  (共享的全局记忆)                │
         └─────────────────────────────────┘

┌─────────────────┐
│   项目 A        │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────┐
│  project_a_memory/              │
│  (项目 A 独立记忆)               │
└─────────────────────────────────┘
```

## 配置方案

### 方案 1: 完全共享 (推荐给个人用户)

**目标**: 所有 AI 应用共享一个统一的记忆库

**优点**:
- 知识积累在一个地方
- 跨应用的上下文连续性
- 简化管理

**缺点**:
- 不同项目的记忆混在一起
- 可能有隐私问题 (如果多人使用)

**配置**:

```json
// 所有应用都使用相同的全局路径
{
  "command": "python",
  "args": [
    "path/to/server.py",
    "--storage-path",
    "C:/Users/You/Documents/MyAIMemory"  // 统一路径
  ]
}
```

### 方案 2: 完全隔离 (推荐给团队/多项目)

**目标**: 每个项目/应用使用独立的记忆库

**优点**:
- 记忆隔离，互不干扰
- 适合多客户/多项目
- 隐私保护

**缺点**:
- 知识无法跨项目复用
- 需要管理多个记忆库

**配置**:

```json
// 每个项目使用独立路径
{
  "command": "python",
  "args": [
    "${workspaceFolder}/server.py",
    "--storage-path",
    "${workspaceFolder}/memory"  // 项目内路径
  ]
}
```

### 方案 3: 分层共享 (推荐给高级用户)

**目标**: 通用知识共享 + 项目记忆隔离

**实现**: 使用符号链接或多个 MCP 实例

**配置 A: 双 MCP 实例**

```json
{
  "mcpServers": {
    // 全局记忆 MCP
    "global-memory": {
      "command": "python",
      "args": [
        "path/to/server.py",
        "--storage-path",
        "C:/GlobalMemory"
      ]
    },
    // 项目记忆 MCP
    "project-memory": {
      "command": "python",
      "args": [
        "${workspaceFolder}/server.py",
        "--storage-path",
        "${workspaceFolder}/memory"
      ]
    }
  }
}
```

**使用**:
- 通用知识: 调用 `global-memory` 的工具
- 项目记忆: 调用 `project-memory` 的工具

**配置 B: 符号链接 (高级)**

```bash
# 在项目记忆中创建指向全局知识库的链接
cd project_memory/
ln -s ~/GlobalMemory/knowledge ./global_knowledge

# 现在项目可以访问全局知识，但日志是独立的
```

## 使用场景

### 场景 1: 个人知识管理

**需求**: 在所有 AI 应用中共享个人知识库

**配置**: 全局共享模式

```json
// 所有应用使用相同配置
{
  "command": "python",
  "args": [
    "path/to/server.py",
    "--storage-path",
    "~/Documents/MyKnowledgeBase"
  ]
}
```

**效果**:
```
你在 VS Code 中: "记住，我喜欢使用 TypeScript"
你在 Claude Desktop 中: "我的编程偏好是什么？"
AI: "你喜欢使用 TypeScript" ✅
```

### 场景 2: 多客户项目管理

**需求**: 不同客户的项目记忆完全隔离

**配置**: 项目隔离模式

```json
// 客户 A 项目
{
  "args": ["server.py", "--storage-path", "./client_a_memory"]
}

// 客户 B 项目
{
  "args": ["server.py", "--storage-path", "./client_b_memory"]
}
```

**效果**: 客户 A 和客户 B 的信息完全隔离，保护隐私

### 场景 3: 工作与个人分离

**需求**: 工作记忆和个人记忆分开

**配置**: 混合模式

```json
// 工作项目
{
  "args": ["server.py", "--storage-path", "~/Work/AIMemory"]
}

// 个人项目
{
  "args": ["server.py", "--storage-path", "~/Personal/AIMemory"]
}
```

### 场景 4: 团队协作 (高级)

**需求**: 团队成员共享项目记忆

**配置**: 使用共享存储 (如网络驱动器、Git 仓库)

```json
{
  "args": [
    "server.py",
    "--storage-path",
    "//SharedDrive/TeamProject/memory"  // 网络共享路径
  ]
}
```

**注意**: 需要处理并发写入问题

## 最佳实践

### 1. 选择合适的模式

**个人用户**:
- ✅ 推荐: 全局共享模式
- 理由: 简单，知识积累效果好

**团队/多项目**:
- ✅ 推荐: 项目隔离模式
- 理由: 隐私保护，互不干扰

**高级用户**:
- ✅ 推荐: 混合模式
- 理由: 灵活，兼顾共享和隔离

### 2. 记忆库命名规范

```
推荐的命名方式:

全局记忆:
- ~/Documents/AIMemory
- ~/.adaptive-agent/memory
- C:/Users/You/GlobalAIMemory

项目记忆:
- ${workspaceFolder}/agent_memory
- ${workspaceFolder}/.ai_memory
- ./project_memory

客户记忆:
- ~/Clients/ClientA/memory
- ~/Projects/project-alpha/memory
```

### 3. 备份策略

**全局记忆** (重要！):
```bash
# 定期备份
cp -r ~/Documents/AIMemory ~/Backups/AIMemory_$(date +%Y%m%d)

# 或使用 Git
cd ~/Documents/AIMemory
git init
git add .
git commit -m "Memory snapshot $(date)"
```

**项目记忆**:
- 通常随项目一起备份
- 可以加入 Git (如果不包含敏感信息)

### 4. 隐私考虑

**敏感项目**:
- ✅ 使用项目隔离模式
- ✅ 不要共享到全局记忆
- ✅ 定期清理敏感信息

**个人项目**:
- ✅ 可以使用全局共享
- 注意不要记录密码等敏感信息

## 注意事项

### 1. 并发写入

**问题**: 多个 AI 应用同时写入同一个记忆库

**风险**:
- 文件冲突
- 数据丢失
- 索引不一致

**解决方案**:
```python
# 当前版本: 最后写入者胜出 (Last Write Wins)
# 未来版本: 考虑添加文件锁机制
```

**建议**:
- 避免同时在多个应用中进行大量写入
- 如果需要，使用项目隔离模式

### 2. 路径变量

**VS Code 变量** (支持):
- `${workspaceFolder}` ✅
- `${userHome}` ✅

**Claude Desktop** (不支持变量):
- 必须使用绝对路径

### 3. 跨平台路径

**Windows**:
```json
"--storage-path", "C:/Users/You/Memory"  // 推荐使用 /
"--storage-path", "C:\\Users\\You\\Memory"  // 或使用 \\
```

**macOS/Linux**:
```json
"--storage-path", "/Users/You/Memory"
"--storage-path", "~/Documents/Memory"  // ~ 会自动展开
```

### 4. 性能考虑

**大型记忆库**:
- 索引构建时间会增加
- 搜索速度可能下降

**建议**:
- 定期归档旧记忆
- 使用项目隔离减小单个记忆库大小

## 总结

### 记忆共享的核心原则

```
相同的 storage-path = 共享记忆
不同的 storage-path = 独立记忆
```

### 选择指南

| 场景 | 推荐模式 | 配置 |
|------|----------|------|
| 个人用户 | 全局共享 | 所有应用使用相同路径 |
| 多项目开发 | 项目隔离 | 每个项目独立路径 |
| 团队协作 | 项目隔离 + 共享存储 | 网络路径 |
| 工作/个人分离 | 混合模式 | 不同路径 |

### 关键要点

1. **默认行为**: 不指定路径 = 全局共享
2. **灵活配置**: 通过 `storage-path` 控制共享范围
3. **跨应用互通**: 完全支持，这是一个强大的特性
4. **隐私保护**: 使用项目隔离模式
5. **备份重要**: 定期备份全局记忆库
